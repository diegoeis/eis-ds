# Layout

How to set up a page or piece built with the system.

## 1. Files to load

A piece is a standalone HTML file. It links one stylesheet:

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="icon" href="<src>/shared/brand/favicon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="<src>/shared/brand/apple-touch-icon.png">
<link rel="stylesheet" href="<src>/<scope>/<scope>.css">
<style>/* this piece's layout only */</style>
```

- `<src>` is the relative path to the `src/` folder at the repository root. From `site/examples/<kind>/` it is `../../../src`.
- `<scope>` is `web` (websites, landing pages, docs) or `app` (dashboards, tools). See §7.
- In a project outside this repository, link `dist/eis-<scope>.min.css` instead: one minified file with the same content and no chained imports. It is generated by `scripts/build-css.py`.
- `<scope>.css` is the only stylesheet to link. It imports `../shared/shared.css` (fonts, shared tokens, base, elements), then the scope tokens and components. Keep `shared/` next to the scope folder. The preconnect lines are optional: they make the fonts load faster.
- `shared.css` imports the fonts, the shared tokens, the base and the elements. The base already sets box-sizing, margins, body type, canvas background and focus. Don't repeat it.
- The piece's `<style>` contains **layout only**: grids, regions, positions, page-specific arrangements. It MUST NOT redefine buttons, chips, fields, tables, panels or any shared element.
- No frameworks or libraries (React, Tailwind, Bootstrap, icon fonts). One exception: Lucide draws the SVG icons (`elements.md`, "Icons"). Load it with `shared/js/icons.js` only when the page has icons.
- The favicon is in `src/shared/brand/`: `favicon.svg` (browser tab) and `apple-touch-icon.png` (180×180, home screen). It is the same in every scope. In a project outside this repository, copy both files next to the page and link the copies. A project with its own brand can use its own favicon.

## 2. Page skeleton

```html
<!doctype html>
<html lang="en">
<head>…files above…</head>
<body class="eis-app-shell">
  <header class="eis-app-topbar">…menu button, page name…</header>
  <aside class="eis-app-sidebar" id="sidebar" aria-label="Sidebar">
    <nav class="eis-app-nav" aria-label="Main">…</nav>
  </aside>
  <main class="eis-app-main">
    <header>
      <nav class="eis-breadcrumb eis-label" aria-label="Breadcrumb">…</nav>
      <h1>Page title</h1>
    </header>
    <section class="eis-panel" aria-labelledby="…">…</section>
  </main>
</body>
</html>
```

A web page (website, landing, docs) uses the web scope instead:

```html
<body>
  <div class="eis-web-sheet">
    <header class="eis-web-wrap eis-web-grid eis-web-header">…</header>
    <main>
      <section class="eis-web-hero" aria-labelledby="hero-h">…</section>
      <section class="eis-web-section" aria-labelledby="…">…</section>
    </main>
    <footer class="eis-web-wrap eis-web-grid eis-web-footer">…</footer>
  </div>
</body>
```

Element roles:

| Region | Element |
|---|---|
| Sidebar / side navigation | `<aside aria-label="…">` — also when it becomes a drawer on mobile |
| Navigation lists | `<nav aria-label="…">` + `<ul>` |
| Page or section heading area | `<header>` (never for the sidebar) |
| Main content | `<main>`, one per page |
| Content blocks | `<section aria-labelledby>` (has a heading) or `<article>` (stands alone) |
| Footer of page, panel or sidebar | `<footer>` |
| Dates and times | `<time datetime="…">` |

- Headings in order, one `<h1>` per page. Panel titles are `h2`/`h3` with the `eis-label` class — the visual size doesn't decide the level.
- Interface text and file names in **English**. Example content is **fictional**: invented first names, invented codes like `PLT-204`. Never use real people, clients or data.

## 3. Spacing the page

| Where | Space |
|---|---|
| Page padding | `--space-300` desktop, `--space-200` below 1024px |
| Gap between page regions (header, metric row, panel grid) | `--space-300` |
| Gap between panels in a grid | `--space-200` |
| Panel padding, row padding | `--space-200` |
| Inside components | `--space-100` |

Surfaces: page on `--surface-canvas`, content in `--surface-panel` panels. Nothing else. No background grid, no gradients, no shadows.

## 4. Grids and responsiveness

Every piece MUST work from 360px to wide screens with **no horizontal scroll**, no clipped text and no overlap.

- Fluid first: `grid`, `flex`, `minmax`, `clamp()`. Breakpoints only where the composition breaks.
- Auto grids MUST use `minmax(min(<px>, 100%), 1fr)`:
  ```css
  grid-template-columns: repeat(auto-fit, minmax(min(250px, 100%), 1fr));
  ```
  A bare `minmax(250px, 1fr)` overflows when the container is narrower than 250px.
- Grid and flex children that contain text: `min-width: 0` (or `minmax(0, 1fr)` columns) so long text wraps instead of pushing the layout.
- Display titles: `font-size: clamp(--font-size-600, 5vw, --font-size-800)`.
- Typical breakpoints so far:
  - 1280px: the side column drops below.
  - 1024px: the sidebar becomes a drawer, opened from the top bar (`eis-app-topbar`).
  - 760px: tables reflow, metrics go 2 × 2.
  - 420px: toolbar buttons stretch.
- A horizontal nav that can't fit scrolls **inside itself** (`overflow-x: auto` on the nav), never the page.
- Tables: reflow to cards with CSS, or scroll inside a wrapper.

## 5. Slides and fixed-ratio pieces

- Each slide is a container. Set `container-type: inline-size` and `aspect-ratio: 16/9`.
- Size everything inside in container units (`cqw`), so the slide scales as one object.
- Use the same tokens for colour, line and type families. Sizes in `cqw` are the allowed exception to px tokens.

## 6. Data visualisation

- Data as a matrix of equal cells (like device keys) or thin bars. No pie charts, no 3D, no gradients.
- Grey ramp for normal values, `--accent` only for the exception (see `tokens-usage.md` §2).
- Every chart has `role="img"` and an `aria-label` that states the numbers.
- Legends are lists (`<ul>`), `aria-hidden` if the `aria-label` already carries the data.

## 7. Scopes: shared, web and app

eis-ds is several design systems in one. They share the same base and never conflict.

| Folder | Use for | Load | Class prefix | Variable prefix |
|---|---|---|---|---|
| `src/shared/` | Every scope | Imported by each scope entry. Optional `shared/js/icons.js` (with Lucide) for icons | `eis-` | `--color-`, `--space-`, `--ink`… |
| `src/web/` | Websites, landing pages, marketing pages, documentation | `web/web.css` or `dist/eis-web.min.css`, optional `web/js/lines.js` | `eis-web-` | `--web-` |
| `src/app/` | Dashboards, tools, system screens | `app/app.css` or `dist/eis-app.min.css`, optional `app/js/sidebar.js` | `eis-app-` | `--app-` |

To build a website, copy `src/shared/` and `src/web/`. To build a dashboard, copy `src/shared/` and `src/app/`. More scopes (slides, email, docs) follow the same pattern.

Rules:
- `shared` never depends on a scope. Shared elements (button, chip, fields, table, panel) and, later, icons live there.
- A scope's tokens live under its own group (`web.*`, `app.*`) and MAY reference shared tokens: `"{font.size.800}"`. A colour change in shared reaches every scope.
- A scope MUST NOT reference another scope's tokens, variables or classes.
- Every selector in `<scope>/css/components.css` starts with `.eis-<scope>-`. A scope never styles bare HTML or shared classes on their own. It MAY place a shared element in its own context (`.eis-app-task-table.eis-table`) for layout only.
- `scripts/build-tokens.py` validates the token rules. `scripts/check-css.py` validates the CSS rules. Both MUST pass.
- A pattern used on two or more pages goes into the scope CSS. A pattern used on one page only stays in that page's `<style>`.

### Rows of fields

`eis-app-add-bar`, `eis-app-form-row` and `eis-app-filters__fields` lay out their `eis-field`s the same way:

- Each field starts at a base width and never gets narrower than it. The base is the field's width helper (`eis-width-100` … `eis-width-500`), else the row's default: `--app-size-form-field` (256px), or in a filter bar `--app-size-filter-field` (192px) and `--app-size-filter-search` (224px). `eis-width-fit`: the content's width is the base.
- The fields share the free room of the row and grow with it. They do not keep a fixed width.
- A field grows up to `--width-400` (360px). A field with a wider base (`eis-width-500`) grows up to its base. So one field never stretches across the whole row.
- `eis-grow` marks the main field of the row (the text of a new task). It grows three times as fast as the other fields and has no `--width-400` limit. Use it on one field per row, or on none.
- A field goes to the next line only when it no longer fits. A field on a new line starts at the left.
- Write no width and no `flex` for this in page CSS. To make a field shorter or longer, change its width helper.

```html
<form class="eis-app-add-bar">
  <div class="eis-field eis-grow"><label for="t">Task</label><input class="eis-input" id="t"></div>
  <div class="eis-field eis-width-200"><label for="g">Group</label><select class="eis-select" id="g">…</select></div>
  <div class="eis-field eis-width-fit"><label for="d">Due date</label><input class="eis-input" id="d" type="date"></div>
  <p class="eis-app-inline"><button class="eis-button eis-button--ghost" type="button">Cancel</button><button class="eis-button eis-button--primary" type="submit">Save</button></p>
</form>
```

### Sidebar collapse

The sidebar can collapse to a narrow strip (`--app-size-sidebar-collapsed`). Collapsed, it shows only the toggle. The toggle does not move. Only its arrow turns.

1. Give the sidebar an `id`.
2. Put the toggle last in the sidebar footer. Put links such as Settings in the main nav, not in the footer:
   ```html
   <footer class="eis-app-sidebar__foot">
     <button class="eis-app-sidebar__toggle" type="button" aria-controls="sidebar"
             aria-expanded="true" aria-label="Sidebar" data-eis-app-sidebar-toggle></button>
   </footer>
   ```
3. Load `app/js/sidebar.js` at the end of `<body>`, after the icon scripts (elements.md, "Icons").

The script sets `aria-expanded`. The CSS reads it. The script keeps the choice in `localStorage` (key `eis-app-sidebar`, change it with `data-key`). The main content then fills the free space, up to `--app-size-main` (1200px). Below 1024px the sidebar is a drawer, the toggle is hidden and the collapse has no effect.

### Mobile drawer

Below 1024px the sidebar leaves the page. A top bar takes its place, fixed at the top. Its menu button opens the sidebar as a drawer: it slides in from the left, over the content, and the page behind it is dimmed. Above 1024px the top bar is hidden.

1. Give the sidebar an `id`.
2. Put the top bar first in `<body>`, before the sidebar. The button is on the left, the page name on the right:
   ```html
   <header class="eis-app-topbar">
     <button class="eis-button eis-button--ghost eis-button--icon" type="button" aria-controls="sidebar"
             aria-expanded="false" aria-label="Menu" title="Menu" data-eis-app-drawer-toggle>
       <i data-lucide="menu" class="eis-icon"></i></button>
     <p class="eis-app-topbar__title">Page name</p>
   </header>
   ```
3. Load `app/js/sidebar.js` at the end of `<body>`, after the icon scripts.

The script sets `aria-expanded` on the button. The CSS reads it. When the drawer opens, the focus goes into it, and Tab and Shift+Tab stay inside it. These close the drawer:

- Esc, or a click outside it. The focus goes back to the menu button.
- A click on a nav item: a link, or a button that is not a sub-list toggle.
- A window that grows above 1024px.

The drawer shows the whole sidebar: section labels, nav, and the footer. A footer that holds only the collapse toggle is hidden. Without the top bar, a page has no navigation below 1024px.

### Nav sub-list

An item of the nav can hold a list of sub-items. The arrow of the toggle points right when the list is closed, down when it is open. The CSS draws it (`--icon-chevron-left` from `shared/css/icons.css`): write no icon.

**The item is a page too** (a workspace with its teams): the item is a link, and an arrow-only toggle comes right after it. A click on the name opens the page. A click on the arrow, at the right of the count, opens or closes the list. Give the toggle an `aria-label` and a `title` that name the list.

```html
<li>
  <a href="#workspace/acme">Acme <span class="eis-app-nav__count">40</span></a>
  <button class="eis-app-nav__toggle" type="button" aria-expanded="true" aria-controls="nav-acme"
          aria-label="Acme teams" title="Acme teams" data-eis-app-nav-toggle></button>
  <ul class="eis-app-nav__sub" id="nav-acme">
    <li><a href="#team/growth" aria-current="page">Growth <span class="eis-app-nav__count">12</span></a></li>
  </ul>
</li>
```

**The item only groups the list** (one page per team under "Topics"): the item is a button with the item's text, not a link. A click anywhere on it opens or closes the list.

```html
<li>
  <button class="eis-app-nav__toggle" type="button" aria-expanded="true" aria-controls="nav-teams"
          data-eis-app-nav-toggle>Topics <span class="eis-app-nav__count">12</span></button>
  <ul class="eis-app-nav__sub" id="nav-teams">
    <li><a href="#team/growth" aria-current="page">Growth</a></li>
  </ul>
</li>
```

`app/js/sidebar.js` sets `aria-expanded` on both forms and keeps each list open or closed for the next visit (`localStorage`, key `eis-app-nav:` + the list id). The CSS reads `aria-expanded`. Sub-items are links, styled like the other items. In the mobile drawer a toggle opens and closes its list and the drawer stays open; a link closes the drawer.

### Page head

Every app page starts with `eis-app-page-head`. It sets one standard top for all pages:

```html
<header class="eis-app-page-head">
  <p class="eis-app-page-head__meta">
    <time class="eis-label" datetime="2026-10-26">Monday, 26 October 2026</time>
    <span class="eis-mono">daily/2026-10/2026-10-26.md</span>
  </p>
  <h1>Daily</h1>
  <form class="eis-app-toolbar">…</form>
</header>
```

- `__meta` is optional. It is a full-width row above the title: the first child sits on the left (the page context, e.g. today's date), the last child on the right (a detail, e.g. the source file or the last update). One child only: it stays on the left.
- The `<h1>` is required. The toolbar is optional and sits on the right of the title.
- The main action of the page (New task, New topic) is `eis-button--accent`, with its Lucide icon. It is the accent of the page: use no other accent button on it. Main actions inside panels (each Save) stay `eis-button--primary`.
- Don't put a breadcrumb and a meta row in the same head. Don't build a page head with helper classes or page CSS: use this component.

### Add a scope

1. Create `src/<scope>/tokens/<scope>.tokens.json`. Put every token under the group `<scope>`. Reference shared tokens where a value already exists.
2. Create `src/<scope>/tokens/<scope>.resolver.json`. Copy `src/web/tokens/web.resolver.json` and change the names.
3. Run `python3 scripts/build-tokens.py`. It finds the new scope and writes `src/<scope>/css/tokens.css`.
4. Create `src/<scope>/css/components.css`. Every selector starts with `.eis-<scope>-`. Then create the entry `src/<scope>/<scope>.css`: copy `src/web/web.css` and change the names.
